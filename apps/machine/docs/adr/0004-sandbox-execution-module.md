# Sandbox Execution owns admission, frames, and cancel state

`executeTask` (`src/execution/execution.ts`) owns one Microsandbox from admission to Execution Outcome: it resolves effective limits from `assign.limits`, serializes quota snapshot + create internally, emits every v1 frame through an injected `emit`, keeps in-flight state so `cancel(taskId)` routes through the same lifecycle, wraps cleanup around create so no non-terminal path leaks a sandbox, and fails closed when no agent binary is configured rather than letting the `sh` echo stub report a completed task. A cancelled execution emits no `task-done` (the server owns the cancel) and is left idle `stopped` for TTL reap. We chose this over the injected quota lock, caller-built refusal frames, `onSandboxCreated` registry callbacks, and the silent `sh` default because the lifecycle invariants (ordering, cleanup, cancel, refusal shape) otherwise live in caller comments and duplicated wiring; tests cross the same interface with injected `emit`/`claim` and the mock sandbox driver. Durable replay of terminal frames (task-done, claim-ack) is deliberately out of scope.
