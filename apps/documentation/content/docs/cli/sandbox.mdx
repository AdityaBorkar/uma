`sandbox` helps you inspect and clean up microsandbox sandboxes. Defined in `apps/machine/src/cli.ts:88`, handled by `cmdSandbox` in `apps/machine/src/index.ts:184`. The subcommand is positional and defaults to `list`.

```text
uma-machine sandbox [list|prune] [--json] [--dry-run]
```

## `sandbox list` — see what's there

Shows a `listSandboxes()` table: `id | task | project | status` (`created` cyan, `running` green, `stopped` yellow, `destroyed` red). Add `--json` for the raw array. Always exits `0`.

```bash
uma-machine sandbox
uma-machine sandbox list
uma-machine sandbox list --json
```

## `sandbox prune` — tidy up safely

Removes every sandbox with `status == stopped` (`removeSandbox`). Add `--dry-run` to preview with `would prune <id>` lines. You'll see `<n> stopped sandbox(es)` at the end. Running sandboxes are never touched. Always exits `0`.

```bash
uma-machine sandbox prune --dry-run
uma-machine sandbox prune
```

Typing something else (like `uma-machine sandbox foo`) prints `unknown sandbox subcommand: foo` and exits `1`.

Under the hood we call (`src/sandbox/cli.ts:29`): `create <UBUNTU_IMAGE> -n <name> ... --label task.id= --label project.id=`, `start`, `stop [--force]`, `remove --force`, `list --format json`, `exec <name> -- <cmd>...`. Driver choice is `sdk` then `cli` then fail-closed (`src/sandbox/driver.ts`); tests force the mock with `MSB_MOCK=1`.
