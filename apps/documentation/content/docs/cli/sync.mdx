title: sync

`sync` converges your local config and keeps the receipts in SQLite so you can prove it later. Defined in `apps/machine/src/cli.ts:75`, handled by `cmdSync` in `apps/machine/src/index.ts:130`, implemented in `apps/machine/src/sync.ts:17` (`performSync`).

```text
uma-machine sync [--dry-run] [--json] [--only <k1,k2>]
```

We run `resetAll({ prune: false })` in `ORDERED_KEYS` order, then save receipts with `persistReceiptsBestEffort` and a job id like `local-<timestamp>-<nanoid>`. You'll see:

```text
sync local-1725800000000-Ab3k:
  programs: ok
  systemd: FAILED — unit not found
```

Exit `0` when all is well, else `2` (via `syncExitCode(receipts)`).

## How this relates to the server

Local `sync` only writes SQLite rows on your machine. The **server-acknowledged** half happens when the daemon gets `reset-config { keys: "*" }` (`src/daemon.ts:121`) — same `performSync` ordering, but acked over the socket with the server's `jobId` as `sync-ack`. See [/machine/reset-config](/machine/reset-config).

```bash
uma-machine sync --dry-run
uma-machine sync --only skills --json
```
