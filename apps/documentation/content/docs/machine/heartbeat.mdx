Heartbeats are your machine's friendly check-ins. Built by `buildHeartbeat` in `apps/machine/src/heartbeat.ts`, sent by `sendHeartbeat` in `apps/machine/src/daemon.ts:29`, shaped by `HeartbeatFrameSchema` in `apps/orpc-contract/src/schemas/machine-frames.ts:18`.

```ts
{
  t: "heartbeat",
  machineId: string,        // min 1
  protocol: "v1",
  cliVersion: string,       // e.g. "0.1.0"
  configVersion: string,    // desired-state version
  metrics: { cpu: 0-100, ram: 0-100, disk: 0-100, pids: number[] },
  quotaUsage: { running: number, total: number },
  sandboxes: { id, status: "created"|"running"|"stopped"|"destroyed", taskId, projectId }[],
  scopeHint: string | null, // pressure attribution ("none" normally)
}
```

## How it works

- **Regular ticks:** every `intervalS` via `setInterval(..., intervalS * 1000)` (`src/daemon.ts:165`), plus one right when the socket opens (`onOpen`) and one at startup. `intervalS` comes from `daemonIntervalS()` (floor 2s, default 30s).
- **Saved first, sent second:** `persistHeartbeat(frame)` writes SQLite before `send(frame)` — so even if the network drops, `uma-machine history` still shows what happened.
- **Helpful under pressure:** `evaluateScopeHint()` sets `scopeHint` when host pressure tops `PRESSURE_THRESHOLD_PCT` (90%) with `PRESSURE_ATTRIBUTION_PCT` (60%) attribution sustained for `PRESSURE_SUSTAINED_S` (600s), with a `PRESSURE_COOLDOWN_S` (600s) cooldown. Constants live in `apps/orpc-contract/src/constants.ts:13`.
- **Tidied automatically:** rows older than `UMA_HEARTBEAT_RETENTION_DAYS` (default 30) are vacuumed away.
