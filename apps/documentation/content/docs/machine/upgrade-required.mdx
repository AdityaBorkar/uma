When your machine is too old to speak the current protocol safely, the server sends a kind nudge to upgrade. Schema `UpgradeRequiredFrameSchema` in `apps/orpc-contract/src/schemas/server-frames.ts:48`; handled by `handleUpgrade` in `apps/machine/src/daemon.ts:43`; comparison via `needsUpgrade` in `apps/orpc-contract/src/utils.ts` (semver with a naive fallback).

```ts
{ t: "UPGRADE_REQUIRED", minVersion: string, reason?: string }
```

## What happens

- If `CLI_VERSION >= minVersion`, you're fine — we log an `UPGRADE_REQUIRED ignored` warning and keep running.
- If `CLI_VERSION < minVersion`, we log `UPGRADE_REQUIRED: daemon <cli> < min <min> (<reason ?? "major mismatch">). Re-run install.sh.` and exit `3`.

Exit `3` is reserved for this case across the CLI (see [/cli](/cli)). Wire-frame changes always ship with a major version and go through this path — see [/contracts/versioning](/contracts/versioning).
