Sometimes plans change — `cancel` lets the server ask your machine to stop a task. Schema `CancelFrameSchema` in `apps/orpc-contract/src/schemas/server-frames.ts:20`; dispatched in `apps/machine/src/daemon.ts:158`; implemented by `cancelTask` in `apps/machine/src/execution.ts:563`.

```ts
{ t: "cancel", taskId: string }
```

## What happens

- We mark the in-flight task as cancelled via the in-flight map.
- We run `stopSandbox --force` for that task's sandbox (falling back to a `task.id` label lookup when the map has no entry, e.g. after a daemon restart).
- It's best-effort and idempotent: cancelling an unknown or already-finished `taskId` is a quiet no-op, never an error frame.
- There's no ack frame for `cancel` in `v1` — you'll see completion as the follow-up `task-done { status: "failed" }` or the sandbox going `stopped`.
