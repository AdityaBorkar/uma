## What your machine does (`executeTask`)

1. **Reserves room first** — `snapshotQuota()` + `quotaPreCheck()` + `create` run under an admission lock. Over quota? We emit `quota-exceeded { taskId, limits, usage }` **and** `claim-ack { ok: false, error: "QUOTA_EXCEEDED" }` (`quotaRefusalFrames` in `src/protocol.ts`), log `refused (quota)`, and stop cleanly without leaking a sandbox.
2. **Claims fairly** — oRPC `machines.claim` (raw `POST /api/machines/claim` for the binary) `{ machineId, sandboxId, taskId }`. A `409`/4xx means someone else won, so we send `claim-ack { ok: false, error: CLAIM_REJECTED }`, free the sandbox, and log `rejected (claim ...)`. Network failure after retries gives `CLAIM_UNREACHABLE`. Success sends `claim-ack { ok: true, sandboxId }`.
3. **Starts fresh** — `startSandbox`, then bind the worktree via `ensureBinding` (clone/fetch/checkout `branchForTask(taskId)`, like `task/<short>`; `freshStart` runs `git clean -fdx + reset --hard` first).
4. **Runs + streams** — `execStream` runs the agent binary with secrets redacted (`Redactor` seeded with session + GitHub tokens), splitting output into 256 KB or smaller UTF-8 chunks (`splitChunks`, byte-accurate) and emitting `log { taskId, chunk, stream?: stdout|stderr|system }` per chunk.
5. **Wraps up** — emits `task-done { taskId, status: completed|failed, projectId, result? up to 64k }`, then `stopSandbox` (left `stopped` for later TTL reap — never removed inline).
6. **Cleans up on trouble** — any throw frees the sandbox; `cancelTask(taskId)` checks the in-flight map first, then falls back to the `task.id` label lookup, and runs `stopSandbox --force`.
