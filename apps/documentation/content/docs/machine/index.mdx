Welcome! The daemon (`runDaemon` in `apps/machine/src/daemon.ts:144`) is a friendly WebSocket client: the server sends **commands**, and your machine sends **frames back**. Dispatch lives in `handleFrame` (`src/daemon.ts:155`):

| Server says (`t`) | Your machine | What happens |
| --- | --- | --- |
| `assign` | `handleAssign` → `executeTask` | Runs a task in a sandbox |
| `cancel` | `cancelTask` | Stops a running task's sandbox |
| `reset-config` | `handleResetConfig` → `resetAll` | Converges config, acks each key |
| `UPGRADE_REQUIRED` | `handleUpgrade` | Exits `3` if truly out of date |

Prefer a diagram? See [/visualize/machine](/visualize/machine). For exact wire shapes, see [/contracts/machine-server](/contracts/machine-server).

Good to know: unknown `t` values never crash anything — `parseServerFrame` returns `null` and the frame is logged and ignored (`src/ws-client.ts`, `server-frames.ts:64`). Outbound frames are validated before sending (`assertMachineFrame` / `validateMachineFrame`).

Between commands, the daemon ticks on its own schedule: every `intervalS` it saves a heartbeat to SQLite and tidies up long-stopped sandboxes (`reapStopped`, `UMA_SANDBOX_TTL_S`, default 1h — `running` sandboxes are never touched).
